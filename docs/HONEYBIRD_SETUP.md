# Honey Bird ERPNext setup for RAI signups

The signup + subscription flow needs six one-time configurations on
`honeybird.frappe.cloud`. None of this can be done programmatically —
Frappe requires a System Manager in the desk UI for doctype / custom-
field / plan creation. ~20 minutes total.

> **Architecture note.** Honey Bird stores **RAI accounts and
> subscription state only.** The customer's own ERP credentials never
> touch our server — they live on the customer's device in encrypted
> secure storage and are sent on each login. The bindings recorded
> here (URLs, companies, devices) are policy state ("what is this
> subscription licensed for"), not credentials.

## 1. Customer Group (already done)

Confirm at:
**honeybird.frappe.cloud/app/customer-group/RAI Subscription**

If missing: List → Customer Group → +New →
Name: `RAI Subscription`, parent: `All Customer Groups`.

## 2. Three child-table doctypes

These three doctypes hold the per-Subscription bindings. They are
child tables — they only exist as rows attached to a parent
Subscription, never as standalone records.

Path: **honeybird.frappe.cloud/app/doctype/new** (one form, one save,
× 3 — once for each doctype below).

For ALL three: when creating, check **Is Child Table** ✓ and check
**Track Changes** ✓ (gives per-row audit log). Module: `Subscription`
(or any — doesn't matter for child tables). No custom permissions
needed; child tables inherit from parent.

### 2a. `RAI Device`

| Label | Fieldname | Type | In List View | Read Only | Notes |
|---|---|---|---|---|---|
| Device ID | `device_id` | Data | yes | yes | UUIDv4 generated by the Flutter app |
| Label | `label` | Data | yes | no | Human-readable, e.g. "iPhone 15 Pro" |
| First Seen | `first_seen` | Datetime | no | yes | Auto-set on first login from device |
| Last Seen | `last_seen` | Datetime | yes | yes | Bumped on every login |

### 2b. `RAI URL Binding`

| Label | Fieldname | Type | In List View | Read Only | Notes |
|---|---|---|---|---|---|
| ERP URL | `url` | Data | yes | no | The customer's ERP base URL |
| Nickname | `nickname` | Data | no | no | Optional. e.g. "Iraq HQ" |
| First Seen | `first_seen` | Datetime | no | yes | When this URL was first observed |

### 2c. `RAI Company Binding`

| Label | Fieldname | Type | In List View | Read Only | Notes |
|---|---|---|---|---|---|
| ERP URL | `erp_url` | Data | yes | yes | Which URL this company belongs to (matches a row in URL Binding) |
| Company | `company` | Data | yes | no | The Company doctype's `name` on that ERP |
| First Seen | `first_seen` | Datetime | no | yes | When the customer first picked this company |

The pairing `(erp_url, company)` is what makes Multi-ERP plans work
later — "Acme Iraq" on URL A and "Acme Iraq" on URL B are two
distinct bindings.

## 3. Custom fields on Subscription Plan (3 fields)

These define **the limits of a tier**. The trial plan in step 5 sets
all three to 1; future paid plans relax them.

Path: **honeybird.frappe.cloud/app/customize-form/Subscription Plan**

| Label | Fieldname | Type | Insert After | Default |
|---|---|---|---|---|
| RAI Max Devices | `rai_max_devices` | Int | `cost` | 1 |
| RAI Max ERP URLs | `rai_max_erp_urls` | Int | `rai_max_devices` | 1 |
| RAI Max Companies | `rai_max_companies` | Int | `rai_max_erp_urls` | 1 |

Save.

## 4. Custom fields on Subscription (3 fields, all Table)

These point to the child-table doctypes you just created. They record
**what the customer is actually bound to** — set automatically by the
backend on first login / first request after signup; you don't fill
them in manually.

Path: **honeybird.frappe.cloud/app/customize-form/Subscription**

| Label | Fieldname | Type | Options | Insert After |
|---|---|---|---|---|
| RAI Bound URLs | `rai_bound_urls` | Table | `RAI URL Binding` | `cancelation_date` |
| RAI Bound Companies | `rai_bound_companies` | Table | `RAI Company Binding` | `rai_bound_urls` |
| RAI Registered Devices | `rai_registered_devices` | Table | `RAI Device` | `rai_bound_companies` |

Save.

## 5. Item + Subscription Plan for the trial

Path: **honeybird.frappe.cloud/app/item/new**

Create one Item:
- Item Code: `RAI-SUB`
- Item Name: `RAI Subscription Service`
- Item Group: `Services`
- Maintain Stock: **unchecked**
- Standard Selling Rate: 0.00

Then path: **honeybird.frappe.cloud/app/subscription-plan/new**

Create the trial plan:
- Plan Name: `RAI Free Trial`
- Item: `RAI-SUB`
- Price Determination: `Fixed Rate`
- Cost: `0.00`
- **Currency: USD** — RAI bills in USD across all plans. The backend
  sets `default_currency=USD` on every Customer it creates at signup,
  so the Plan's USD currency validates against the Customer regardless
  of Honey Bird's own company default (IQD). Don't change this to IQD
  — that breaks the validator the moment a paid plan ships in USD.
- Billing Interval: `Month`
- Billing Interval Count: `1`
- **RAI Max Devices: `1`**
- **RAI Max ERP URLs: `1`**
- **RAI Max Companies: `1`**

Optionally also create paid plans you can promote customers to from
the desk later (just change their Subscription's `plan` link):

| Plan Name | Devices | URLs | Companies | Suggested price |
|---|---|---|---|---|
| `RAI Solo Multi-Company` | 1 | 1 | 99 | $79/mo |
| `RAI Team` | 5 | 1 | 99 | $149/mo |
| `RAI Multi-ERP` | 5 | 5 | 99 | $249/mo |
| `RAI Enterprise` | 99 | 99 | 99 | custom |

The backend uses `RAI Free Trial` for new signups and reads the three
`rai_max_*` fields on every protected request. To upgrade a customer,
change the Subscription's `plan` link in the desk — no code change.

## 6. Admin API key for the RAI backend

The backend creates Users + Customers + Subscriptions, plus inserts
rows into the three child tables. It needs an API key from a System
Manager account.

Path: **honeybird.frappe.cloud/app/user/admin@honey-bird.net** (or
whichever System Manager account RAI should act as)

→ Scroll to **API Access** → click **Generate Keys** → copy both:
- API Key (the public part, looks like `5f2a8c...`) — visible
  permanently after generation
- API Secret (the private part) — shown ONCE in a popup; copy it
  immediately or you'll have to regenerate

Store these as Cloud Run secrets:

```powershell
echo "PASTE_API_KEY"    | gcloud secrets create rai-honeybird-key    --data-file=-
echo "PASTE_API_SECRET" | gcloud secrets create rai-honeybird-secret --data-file=-
```

Quick verification:

```bash
curl https://honeybird.frappe.cloud/api/method/frappe.auth.get_logged_user \
  -H "Authorization: token YOUR_KEY:YOUR_SECRET"
```

Expected response: `{"message": "admin@honey-bird.net"}`. If you see
`{"message": "Guest"}` instead, the keys aren't being read — usually a
copy-paste whitespace issue.

## 7. Verify: try a signup manually

Once the backend deploys with the admin keys, hit:

```bash
curl -X POST https://erp.honey-bird.net/api/v1/auth/signup \
  -H "Content-Type: application/json" \
  -d '{
    "email": "test@example.com",
    "password": "test1234",
    "full_name": "Test User",
    "phone": "+9647712345678",
    "erp_url": "https://your-erp.frappe.cloud",
    "erp_username": "owner@your-erp.com",
    "erp_password": "their-erp-password",
    "device_id": "test-device-uuid",
    "device_label": "Test"
  }'
```

In honeybird.frappe.cloud you should now see:
- A new User: `test@example.com`, type=Website User, **NO ERP credentials**
- A new Customer: `Test User`, group=RAI Subscription
- A new Subscription: party=Test User, plan=RAI Free Trial,
  trial_period_end = today + 30 days. Open it and check:
  - **RAI Bound URLs** has 1 row with the test URL
  - **RAI Bound Companies** is empty until the first dashboard load
    (which fires the company picker / auto-bind)
  - **RAI Registered Devices** has 1 row with `test-device-uuid`

Delete the test records when verified.
